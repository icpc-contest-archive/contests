# Data scan, 2026-11-23: what was fixed, what is open

Fredrik asked for as many agents as possible to scan the catalogue for issues and missing data, fix
what can be fixed directly and report the rest. 33 agents ran in two waves over the catalogue, the
archive and the web, and a 34th checked a sample of the result. Every agent wrote fix operations (`ops.json`, with the evidence for each change)
and a report. The fixes were applied centrally with `tools/apply_scan_ops.py`, which refuses an
operation whose target has changed since the agent looked, so agents could not overwrite each other.
Where two agents disagreed, or a change rested on medium evidence, it was held back (listed below).

Everything is on the branch `data-scan-2026-11-23`: three commits on top of `main` at 31511d8 (the
scan worked on f9d91fe while another session kept committing to `main`; at the end every fix was
replayed onto `main` with the same guarded applier, so the branch merges without conflicts). Validator:
0 errors, 3 warnings (was 7).

**Independent check.** A separate agent that made none of the changes re-verified a stratified random
sample of 102 applied changes (4 per agent, 14 Live Archive links) against the pages and copies they
cite: 99 correct, 3 wrong (about 1.2 % when weighted by each agent's share). The three were fixed:
rmc-2004's count and letters had come from the 2005 board (reverted to 8); the 1998 NEERC results page is
`rankings`, not a scoreboard, for the Western subregion; and the Japan domestic qualifier results filed on
japan-2007/2008/2010/2011/2017 now carry `scope: domestic qualifier`. Report: `reports/data-scan-2026-11-23/verify.md`.

**Replay onto `main`.** Of the 3,261 non-Live-Archive operations, 3,157 applied to `main` unchanged; 104
were skipped because `main` had changed the same field meanwhile (103 Live Archive links of the
judge-links agent, now covered by the row above, and thailand-2025's roles, where `main` is newer).

Every change carries its evidence in the agent's `ops.json`; a changed fact also got a provenance line
in the series file ("… read from <url> (data scan 2026-11-23)"). Agent reports: `reports/data-scan-2026-11-23/`;
their full lists: `data/data-scan-2026-11-23/`.

## Questions for Fredrik

Grouped; each lists the recommendation. Examples and full lists are in the agent report named.

### Sources

1. **Sources whose held copy is not about the contest at all** (about 70: a department site, a photo gallery,
   a Telegram page, a ministry order; `sr-roles-a`, `sr-roles-b`). Remove, keep as lost, or keep with no
   roles? *Recommendation:* remove where the address never served the edition; keep the organisers' own
   addresses as lost.
2. **Hub pages that only link to results or problems** (sppcontests, swerc.eu 2023, icpc.global WF 2023,
   bapc Problems pages, ACPC calendar entries, ICPC China quota pages). *Recommendation:* `web` for hubs;
   `problemset` only where the page's job is to hand out the contest's files (the describe rubric).
3. **ICPC News pages `news.icpc.global/wfYYYY`** are `web` for some World Finals and `rankings` + `report`
   for others; history pages (wf-1992..1999, scusa-1989/90/94) are `web`. *Recommendation:* `report` +
   `rankings` for both (`web-a`; wf-2015 and wf-2022 held until ruled).
4. **Series sites cited as `web` of many editions with no `as_of`** (125 addresses; `urls`). Pin each
   edition to a snapshot of its season, or accept "today's page"? *Recommendation:* pin, as was done for
   the NERC subregion pages (176 pinned; 67 have no snapshot of their edition and stay unpinned; `pins`).
   Related (`pins`): an address whose captures show another contest's document (gwalior-2014's problem
   PDF is the Kanpur 2013 set) — remove rather than keep as lost? A page with this edition's heading over
   another edition's results was treated as the other edition's. Do framesets and JS shells that show only
   a title count as a `web` snapshot (frames were pinned)? Don't run `wayback_history.py --decide --write`:
   14 of its 137 picks were wrong.
5. **70 Kattis problem-sources pages say "No data found"** (`sr-notdoc`); none is in the public list and
   Wayback has none. Can you check them against the Kattis export? Then remove the empty ones.
6. **Qualifier, online and preliminary rounds filed as the onsite contest's results without `scope`**
   (Tehran 2013/15/24/25, aec-2023, Amritapuri, Beijing, Japan domestic, Saudi qualifications, kanpur-2021;
   `sr-wrong`, `urls`, `results-afar-asia`). Should a preliminary's results or selection list count for the
   contest at all? *Recommendation:* keep them, always with `scope`, and never as the contest's level.
7. **SoCal**: 13 `web` sources `socalcontest.org/history/<year>/results-<year>.shtml` (1979–1993) never
   existed; ecna-1997's only `web` is Waterloo's World Finals page. *Recommendation:* remove (`results-na`).
8. **Thin or reused addresses**: the 14 `icpc.bubt.edu.bd/YYYY` dhaka sources all serve the 2025 front page;
   `icpc.kateb.edu.af` now serves gambling spam (kabul-2025 unpinned); four `xxx.yyy.edu` placeholders
   (`web-b`).

## To run on the Mac

Merge the branch (the main checkout has two uncommitted files of the other session's; the branch does not
touch them):

```
cd ~/Claude/icpc-contests/contests && git merge data-scan-2026-11-23 && python3 tools/validate.py && git push origin main
```

Capture what the scan found but we do not hold (new sources, re-pinned snapshots; 169 + 199 recapture
items are listed in `data/data-scan-2026-11-23/sr-notdoc.json` and `archive.json`). Seven new sources sit on
addresses that are overwritten each season (`web-a`): capture them first.

```
cd ~/Claude/icpc-contests/contests && python3 tools/make_capture_queue.py --fresh-days 90 && cd .. && PHASES="urls" PROXY_LIMIT=40 caffeinate -i bash finish-captures.sh
```

CMS standings for the newly cited pages (aec-2025, euc-2026, nordic-2025, vietnam-national-2023 are missing
from the dumps; the top-up is resumable, run it until it says nothing is left), then the bake:

```
cd ~/Claude/icpc-contests/contests && python3 tools/topup_icpc_standings.py && python3 tools/bake_icpc_standings.py --write
```

## Notes

- Agents read our held copies first, then live pages and Wayback; the Wayback Machine throttled or
  refused for long stretches, so several hunts are partial. Each report lists what was not reached and
  what was tried, so a later round can resume.
- 1,442 stray `tmp_obj_*` files (23 MB) sit in `contests/.git/objects` from git's failed unlinks on the
  mount; `git prune` on the Mac clears them.
- If `main` moves on before the merge and the merge conflicts, the fixes can be replayed again: every
  applied operation is logged with its evidence in `_scan-2026-11-23/replay-applied.jsonl`, and
  `tools/apply_scan_ops.py --partial` applies what still resolves and lists the rest.
- The working files of the scan (agents' scratch folders, logs, the replay lists) stay in
  `~/Claude/icpc-contests/_scan-2026-11-23/`; nothing there is needed after the merge.
